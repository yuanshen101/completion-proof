# Completion Proof

Evidence receipts for coding completion — tied to the current source/test/artifact
revision, not to an agent's memory of a command.

Completion Proof is a native Hermes plugin. Operators declare checks (argv,
timeout, source/test/artifact globs); the plugin runs them locally, fingerprints
the declared files with SHA-256, records **PASS / FAIL / UNKNOWN** receipts, and
turns an old PASS **STALE** as soon as a relevant file or the check definition
changes.

## What a PASS proves

Only that the configured command exited `0` before its timeout on the declared
source/test/artifact scope, with the recorded file hashes. It does **not** prove
that all software is correct, that every test ran, or that an artifact was
generated by the command. Evidence is local and not cryptographically
tamper-proof. A command can exit 0 while collecting zero tests; the plugin does
not parse output as proof, and declared source/test globs that match no files are
UNKNOWN unless the operator explicitly enables `allow_missing_patterns`.

## Install

```bash
tar -xzf evidence/package/completion-proof-0.1.5.tar.gz \
  -C "${HERMES_HOME:-$HOME/.hermes}/plugins"
hermes plugins enable completion-proof
hermes plugins doctor completion-proof --ci
```

Requires Hermes `>=0.22.7`; current 0.1.5 evidence was exercised with `0.23.0`. Review the check
configuration before trusting it.

## Rule 13 disclosure

- Configured commands run with the operator's OS privileges. They are **not a
  sandbox** and may themselves use the network or read files; the plugin does not
  restrict what an operator-configured command does.
- The deterministic plugin engine makes no network calls and no LLM calls of its
  own.
- Workspace reads are limited to declared source/test/artifact globs; the
  fingerprint refuses credential-shaped paths (`.env`, `auth.json`, `.ssh`, key
  material, etc.) even if a glob matches them.
- Plugin state is SQLite metadata/storage/retention under the profile's
  `plugin-data/completion-proof/`; no daemon and no telemetry.
- `pre_verify` is a bounded one-shot request, not a fail-closed gate.
- The plugin never reads raw credential stores.
- Configuring a check is the operator's authorization for that check and scope.

## Limits

- Native Windows is untested; POSIX no-follow traversal returns UNKNOWN where the
  platform cannot offer the same guarantee.
- A deliberately escaped descendant cannot be killed through the parent process
  group; output is bounded and reported incomplete/UNKNOWN.
- Full-agent token cost is not measured; engine calls are network/LLM-free, but a
  nudge can add agent turns.
- The public repository, catalog SHA pin, X post, Typeform submission and the
  operator's own eligibility decision are external human steps. Mauritius is not a
  worker-side blocker and eligibility is not claimed confirmed.
